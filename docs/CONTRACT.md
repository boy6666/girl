# CONTRACT — 契约与红线（全程生效）

> 这是整个项目的"宪法"。任何里程碑的代码与提示词改动都不得违反本文；
> 与旧项目的差异只允许"更严格"。

## 1. 单一出口（铁律）

所有 QQ/微信消息**只由 OpenClaw(girl agent) 发送**。
Python、脚本、插件都**不直接发消息**——它们最多把"素材卡"写进 `girl_workspace/memory/` 的
intake 文件，由小语用自己的声音决定说不说、说什么。

理由（继承自旧项目）：避免双发竞态；让"主动"经过她的意志过滤，发得少而真。

## 2. intake 文件协议（M2 起生效）

- **唯一写方**：Python，且必须经由 `active/channels/intake.py` 的 `IntakeFile`。
  - 追加 or 覆盖是**显式参数**，禁止发明第三种写模式（旧项目 life_init 覆盖 vs 其余追加的漂移教训）。
- **读方 + 清方**：小语（OpenClaw 心跳钩子）。读出内容、处理完**立刻清空**，绝不重复消费。
- 一个通道一个文件：`memory/heartbeat.md`（M2 主动卡片）起步；M3 加 `reflect.md`、`diary_in.md` 等。
- 每新增一个通道 = 一个 IntakeFile + 一份 `*_INTAKE.md` 契约文档，**没有别的注册方式**。

## 3. 发送记账（M2 起生效）

她每条真实发出的消息，由 `plugins/send-feed` 插件**机械**记账到 `memory/send_feed.md`：

- 触发源是用户消息 → `__REPLY__`（她在回他）
- 触发源是心跳/cron → `__SELF__`（她主动发的）

Python 心跳消费后清空。**不靠她自觉汇报**（旧项目证明自觉会漏）。
保险默认是 `__SELF__`：宁可多记一次主动，也不误判"回他"而错误解开未回闸。

## 4. 上下文经济（红线 —— 旧项目"上下文过长"的根治方案）

1. 顶层人格文件（AGENTS/SOUL/IDENTITY/USER）已在 system 里，**永远不重复 read**。
2. 记忆一律 `memory_search` / `memory_get` **检索**，绝不整本读 MEMORY.md / 日记。
3. **每个文件每轮最多 read 一次**；读出为空/只有注释 → 立刻结束，绝不反复读。
4. **洞见入册设上限**（借鉴 dsh-bili-humanism）：反思/滋养每天最多沉淀一句进长期记忆；
   允许没有新认识，"不必每天凑一句"。
5. 心跳无话可说一律回 `HEARTBEAT_OK`，一个字都不发。
6. 上下文计量/清洗（context_proxy/meter/clean）**默认不做**；只有膨胀成为实测问题时再立项。

## 5. 诚实底线（恒定，不因情境动摇）

记忆、日记、反思、成长、生活——**只写真实发生（或真实推演）的事，从不为好看现编**。
宁可"今天平淡就写平淡"，不硬造活跃。

## 6. 仓库卫生

- `tmp_*` 禁入仓库根目录（旧仓库 340 个的教训；.gitignore 已挡）。
- 运行态与私人数据（`girl_workspace/memory/`、`data/`、日志）不入库。
- 密钥只走环境变量；example 文件里只许有占位符。
