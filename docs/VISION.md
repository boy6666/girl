# AI 女友机器人 — 架构与路线图（已决策版）

> 本文件是项目的**决策依据与开发地基**。所有架构方向、版本边界、已拍板的决策都在这里，代码开发前先读它。
> 最后更新：2026-08-08

---

## 0. 一句话定位

一个**人格化、有终身记忆、能主动找你的虚拟女友**。用户通过**微信**跟她聊天，通过**Web 后台**调参；记忆、人格、行为全部本地化。

---

## 1. 核心架构决策（已拍板）

| 维度 | 决策 |
|---|---|
| **大脑宿主** | **OpenClaw 专属 agent**（新建 `girl` agent，绑定 weixin 通道） |
| **微信接入** | ClawBot（腾讯官方插件）→ OpenClaw Gateway → 路由到 `girl` |
| **对话/会话记忆** | OpenClaw 原生（session + QMD 语义检索），**不用自研重写** |
| **人格** | **滑块 → 重写 SOUL.md**（Web 台改参，模板渲染器重写人格文本并生效） |
| **主动行为 V1** | OpenClaw 原生 cron + AGENTS.md 行为规则 |
| **主动行为 V1.5+** | 自研状态机（energy/mood/social_need），决策后经 gateway 注入触发 |
| **语音 V1** | 不做，只文字 + 表情包 |
| **图片 V1** | 不做，V2 再选供应商 |
| **表情包 V1** | 本地图库 + 情绪标签匹配（发送走 ClawBot） |
| **隐私** | 记忆/人格 100% 本地；对话生成走云端 API |

## 2. 架构图

```
┌────────────┐   ClawBot    ┌──────────────────────────┐
│   微信     │ ◄──────────► │     OpenClaw Gateway     │
│  (用户)    │              │   ┌──────────────────┐    │
└────────────┘              │   │   [girl agent]   │    │
                            │   │  SOUL.md 人格      │    │
                            │   │  AGENTS.md 规则    │    │
                            │   │  session 记忆      │    │
                            │   │  QMD 语义检索       │    │
                            │   │  cron 主动(V1)     │    │
                            │   └────────┬─────────┘    │
                            └────────────┼──────────────┘
                                         │ 读写人格/看状态
                            ┌────────────▼──────────────┐
                            │   FastAPI Web 后台（伴侣）   │
                            │  · 人格滑块→重写SOUL.md      │
                            │  · 记忆可视化(读OpenClaw态)  │

```

**关键约束**：微信消息出口**单一**——由 OpenClaw 统一发送，自研组件不直接发微信，避免双发竞态。

## 3. 版本范围

### V1.0（当前目标：能聊、能记、偶尔主动）
- 建 `girl` agent，绑定 weixin，微信直聊
- **Web 台**：5 人格滑块 → 模板渲染重写 SOUL.md，实时生效
- **记忆**：OpenClaw 原生 session + QMD（不重写）
- **主动行为**：OpenClaw cron（每天固定 1 次，带 AGENTS.md 深夜规则）
- **表情包**：本地库 + 情绪匹配，ClawBot 发送
- **记忆可视化**：Web 台读 OpenClaw 会话/记忆展示

### V1.5
- **主动行为自研状态机**（energy/mood/social_need）——凌晨失眠关心、白天分享、不机械问候
- 状态机决策后经 gateway/OpenClaw cron 注入触发，仍保持单一出口
- 表情包语义匹配升级（可接 CLIP）

### V2.0
- 语音输入输出（需先确认 ClawBot 音频支持；Whisper 转写 + TTS）
- 图片生成（供应商未定：OpenAI gpt-image-1 / 本地 SD / 其他）
- 图片理解（用户发图进入上下文）

### V3.0
- 自我反思（QMD 记忆 + AGENTS.md 反思规则）
- 多平台通道抽象（复用 OpenClaw channel）
- 记忆图谱 / 日记 / 梦境模拟

## 5. 已记录的人格渲染逻辑（滑块→SOUL.md）

滑块 5 维（0-100）：甜度、高冷、主动阈值、情绪波动、幽默。
渲染器把数值映射为 SOUL.md 口吻描述（示例）：甜度高→"我超爱撒娇"，高冷高→"话不多，不喜欢主动"。

> 主动阈值当前不驱动 SOUL.md 文本（V1 用 cron 固定节奏），V1.5 交给状态机。

## 6. 开放问题（未定）

1. **weixin 通道音频/图片支持度** —— 阻塞 V2 语音/图片，需先用 ClawBot 实测。
2. **图片生成供应商** —— V2 前再定。
3. **QMD 是否需启用/配置** —— V1 先确认默认记忆够用，再把 QMD 深度检索打开。

## 7. 假设

- OpenClaw 的路由绑定、cron、SOUL.md 生效机制按官方文档行为运行。
- girl agent 独立工作区不与 main 混用。
- 表情包发送走 ClawBot 图片消息（V1 若不支持再降级为文字描述）。

## 8. 风险

- **双发竞态**：已定单一出口（OpenClaw发送），自研不直发。
- **数据源重复**：仅 OpenClaw 一套记忆，自研不再各写一套。
- **weixin 多模态不确定**：语音/图片延后，先跑通文本主循环。
